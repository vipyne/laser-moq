Caveats

    

      Both streams come from one ffmpeg encode (same bitrate, GOP, encoder), so the comparison is
      apples to apples. Measurements run on the publisher machine: the burned-in clock and the
      local clock are the same clock, so there is no NTP skew — but screenshot timing adds about
      ±50 ms of noise to every glass-to-glass sample. hlsjs-api rows are the
      latency hls.js itself reports, not glass-to-glass, shown for cross-checking only.
      Since Task 6, the harness records each run's HLS tuning receipt (client preset,
      part target, sync target) straight off window.__hls — shown as a
      hover tooltip on hls table rows and appended to the HLS tile's subtitle; runs from
      before then have no tuning receipt and render as before. The viewer page's Mode A
      "typical" and Mode B "ragged" presets are the two tuning stories this compares.
